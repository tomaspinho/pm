## Build / Lint / Test Commands

All commands are mise tasks. Run `mise tasks ls` to see the full list.

```bash
# Setup — install all tools and dependencies
mise install              # install Go, air, templ, tailwindcss, goose, golangci-lint
mise run setup            # install tools + go mod download + generate code

# Development
mise run dev              # start Air hot-reload server (generates templ + CSS first)
mise run dev:css          # run TailwindCSS in watch mode (separate terminal)

# Build
mise run templ:generate   # generate Go code from .templ files
mise run css:build        # build + minify TailwindCSS
mise run build            # full production build (templ + css + go build)

# Test
mise run test             # run all tests
mise run test:verbose     # run all tests with -v
mise run test:run -- TestFunctionName         # run a single test by name
mise run test:run -- TestFunctionName/subtest # run a specific subtest
mise run test:coverage    # run tests with coverage report → coverage.html

# To run tests for a specific package only:
go test -v ./internal/store/...
go test -v -run TestCreateProject ./internal/store/...

# Lint
mise run lint             # go vet + golangci-lint
mise run lint:fix         # golangci-lint with --fix

# Database migrations
mise run db:up            # apply all pending migrations
mise run db:down          # rollback last migration
mise run db:status        # show migration status
mise run db:create -- add_users   # create new migration file
mise run db:reset         # rollback all + re-apply

# CI (runs build + lint + test in parallel)
mise run ci
```

## Code Style Guidelines

### Go Code

- **Go version**: 1.25+ (set in mise.toml)
- **Formatting**: `gofmt` — no configuration, no exceptions
- **Linter**: `golangci-lint` — run via `mise run lint`

### Imports

Group imports in three blocks separated by blank lines:

```go
import (
    // 1. Standard library
    "context"
    "fmt"
    "log"

    // 2. Internal packages
    "cracked-pm/internal/handler"
    "cracked-pm/internal/store"

    // 3. External dependencies
    "github.com/gofiber/fiber/v3"
    "github.com/jmoiron/sqlx"
)
```

### Naming Conventions

- **Files**: `lowercase.go`, `lowercase_test.go` — no hyphens, no camelCase
- **Packages**: short, single-word, lowercase (`handler`, `store`, `model`)
- **Exported functions**: `PascalCase` — `HandleHome`, `Connect`
- **Unexported helpers**: `camelCase` — `render`, `envOr`
- **Struct fields**: `PascalCase` with `db:"snake_case"` and `json:"snake_case"` tags
- **Handler functions**: `Handle<Action>` pattern — `HandleHome`, `HandleTime`, `HandleCreateProject`
- **Interfaces**: verb-noun or `-er` suffix — `Reader`, `ProjectStore`
- **Constants**: `PascalCase` for exported, `camelCase` for unexported

### Types and Models

- Define domain models in `internal/model/` with both `db:""` and `json:""` struct tags
- Use `time.Time` for timestamps, `int64` for IDs
- Prefer concrete types; use interfaces only at consumption sites

```go
type Project struct {
    ID          int64     `db:"id"          json:"id"`
    Name        string    `db:"name"        json:"name"`
    CreatedAt   time.Time `db:"created_at"  json:"created_at"`
}
```

### Error Handling

- Wrap errors with context: `fmt.Errorf("connecting to database: %w", err)`
- Use `log.Fatalf` only in `main()` for unrecoverable startup errors
- In handlers, return errors to Fiber — use `fiber.NewError(code, msg)` for HTTP errors
- Never silently discard errors. If ignoring intentionally, assign to `_` with a comment

### Fiber Handlers

- Signature: `func(fiber.Ctx) error`
- Use the `render` helper to render templ components:

```go
func HandleFoo(c fiber.Ctx) error {
    return render(c, views.FooPage())
}
```

- For htmx partials, return a templ component (not a full page layout)
- For JSON API endpoints, use `c.JSON()`

### templ Templates

- Place in `views/` — one `.templ` file per page or logical group
- Reusable components go in `views/components/`
- After editing `.templ` files, regenerate: `mise run templ:generate`
- Generated `*_templ.go` files are gitignored — never edit them manually
- Use TailwindCSS utility classes directly in templ markup

### Database (sqlx)

- All database access goes in `internal/store/`
- Use `sqlx.DB` (not raw `database/sql`)
- Use named queries with `:name` syntax for inserts/updates
- Use `db.Get` for single rows, `db.Select` for multiple rows
- Use `db.NamedExec` for inserts/updates with struct binding

```go
func (s *Store) GetProject(ctx context.Context, id int64) (model.Project, error) {
    var p model.Project
    err := s.db.GetContext(ctx, &p, "SELECT * FROM projects WHERE id = $1", id)
    return p, err
}
```

### Migrations (goose)

- Place SQL files in `migrations/` — goose auto-numbers them
- Use `-- +goose Up` and `-- +goose Down` annotations in a single file
- Use `-- +goose NO TRANSACTION` for operations like `CREATE INDEX CONCURRENTLY`
- Both the goose CLI (`mise run db:up`) and the embedded `migrations.FS` read from `migrations/`
- The server runs embedded migrations on startup via `goose.Up(db.DB, ".")`

### CSS / TailwindCSS

- Source file: `styles/input.css`
- Output: `static/css/output.css` (gitignored, generated)
- Use TailwindCSS v4 utility classes directly in `.templ` files
- Run `mise run dev:css` in a separate terminal during development
- Run `mise run css:build` for production (minified)

### htmx

- htmx is vendored at `static/js/htmx.min.js` — do not use a CDN
- Use `hx-get`, `hx-post`, etc. attributes in templ markup
- htmx partial responses should return HTML fragments (templ components without layout)
- Full page loads use the `Layout()` wrapper; htmx swaps do not
